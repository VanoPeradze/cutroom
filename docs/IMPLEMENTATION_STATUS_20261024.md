## This increment: bind the reviewed request to the saved project revision

The existing summary's `isCurrent`/revision checks were local to the browser. The actual `/director` request sent only settings, so a project change saved by another window between review and server admission could be treated as a fresh request against the new project. A queued request could likewise begin on a later revision.

The normal UI now sends `X-Cutroom-Reviewed-Revision`. The server validates this transport header independently of settings, checks it before AI readiness and again at job admission, and passes the revision to the actual Director worker. The worker rejects a changed revision before source processing, cache work or settings/edit commits. The user sees an actionable stale-review response and retains the current edit. The app module cache identifier was advanced for this JavaScript change.

This is **implemented and focused-tested locally, not released**. It does not rewrite instructions or source text, alter duration/style rules, change model defaults, enable experiments or confer semantic approval. Legacy API callers omitting the header retain compatibility and do not gain this additional review binding. Direct out-of-app replacement of source files is not a guarantee added by a project-revision header; existing source-identity checks remain separate.

Changed product files: `server.py`, `cutroom/director.py`, `web/app.js`, `web/index.html`. Tests: new `tests/test_reviewed_request_binding.py` and the actual-generate-request assertion in `tests/frontend_request_review.test.cjs`.
